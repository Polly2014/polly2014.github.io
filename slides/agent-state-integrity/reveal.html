Three bounded lessons

Observation ≠ assurance.
看到错误，不等于下一步被约束。

Local guarantees do not automatically compose.
局部性质不能自动跨阶段继承。

Restoration ≠ safe reuse.
恢复了字节，不等于恢复状态仍可采纳。

这些统计只建立问题背景；本方案需要单独验证的是：跨阶段状态绑定能否被机械检查，并在绑定断裂时失败闭锁。
04 · Failure modes

四类高频失效，都不是“再问模型一次”能解决

共同根因：身份、内容与授权
在阶段边界上没有被绑定
E1

Evidence drift

后续阶段使用了摘要、旧段落或错误 offset，却仍看起来引用同一文档。

M2

Memory drift

压缩悄悄丢掉数字、单位、否定、限定词、冲突或开放依赖。

V3

Stale verification

决策或证据已经变化，Verifier 仍批准先前生成的判断包。

R4

Unsafe resume

checkpoint 混合不同阶段产物，或恢复被修改的 artifact 后继续执行。

核心问题：下游阶段如何证明，它消费的正是上游已经接受的那一份状态？
05 · Core design principle

把 Agent 的每次状态转移
变成可验证的许可条件

方案不依赖某一个 retrieval、compression、verifier、checkpoint 或 hash log。

它把这些组件的输出放进同一个结构化 AgentState，通过连续的内容绑定，使下游只有在上游状态身份仍成立时才能继续。

Identity

这是同一份证据、记忆和决策吗？

Authority

这个组件有权验证、修改或完成吗？

Admissibility

当前状态满足进入下一阶段的条件吗？

16 · Design boundary

不是“用了 hash”，而是这些机制怎样互相授权

individual components are known
the proposed subject matter is their nested coupling

Known component families

  • ReAct reasoning-action loop
  • RAG and source citations
  • prompt / memory compression
  • self-verification and critic agents
  • graph persistence and checkpoints
  • append-only or hash-linked logs
NOT
+

Proposed coupled mechanism

  • exact source record authorizes protected state
  • signature equality authorizes compressed state
  • current fingerprint authorizes verifier result
  • receipt identity authorizes recovery replay
  • the same bindings authorize final output
  • any broken dependency fails closed
边界：单个组件并不构成完整方案。需要验证的是连续授权关系能否减少 silent corruption，并以可控成本维持失败闭锁。

18 · Closing the loop

现在，可以回答开头的问题

相同答案不代表相同执行
有效性来自可验证的状态链
01

要防什么？
证据、记忆、决策与恢复在阶段边界上发生 silent corruption。

02

怎么防？
五层内容绑定让每个下游动作都消费当前、可重放的上游状态。

03

失败怎么办？
拒绝、回退、局部隔离或 typed stop；无效状态不能静默向后传播。

04

证据说明什么？
工程审计支持协议闭合与状态完整性，不把它写成答案全对。
